# 001 — Advantage/Disadvantage combat resolution

## Goal
Replace flat +1 combat modifiers (day/night phase bonus, silver weapon, fortification?)
with an advantage/disadvantage mechanic: roll N extra D6 and take best (advantage) or
worst (disadvantage). Replace the current +1D3 gang-up bonus with one advantage die
per additional ally.

## Acceptance criteria
- `Entity.resolveCombat()` rewritten to roll advantage/disadvantage pools instead of
  flat +1s. All existing call sites still get `{hit, crush, counter, damage}` back.
- Phase bonuses (day favors Hero, night favors Witch), silver weapon, and ally
  gang-up all expressed as advantage/disadvantage instead of +1 / +1D3.
- Fortification bonus decision: keep as flat, or convert — DOCUMENT CHOICE in PR.
- Tests: unit tests for advantage/disadvantage math; combat-sim hit/crush rate
  tables updated; full balance re-run (500 std + 100 2v2 + ai-matrix) with results
  in PR body. Expect win rates to shift — baseline will need updating in CLAUDE.md.
- AI combat estimator (`src/ai.js` expected-damage calcs) updated to use new math.

## File allowlist
- `src/entities.js`
- `src/ai.js` (combat estimation only)
- `tests/combat.test.js` (or new test file)
- `scripts/combat-sim.js` (output format may need updating)
- `CLAUDE.md` (baseline table update after re-balancing)
